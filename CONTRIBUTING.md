# Участие в LiteOffice Docs

Спасибо за интерес к проекту. Приложение развивается в первую очередь для macOS и
Linux; сборки под Windows поддерживаются, но не являются приоритетом.

## Перед началом

- Для уязвимостей не открывайте публичный issue — см. [SECURITY.md](SECURITY.md).
- Для крупных изменений сначала откройте issue с описанием задачи, чтобы не
  потратить время на решение вне объёма проекта.
- Требования к окружению, сборка и полный набор проверок описаны в
  [docs/build.md](docs/build.md).

## Рабочий процесс

1. Форкните репозиторий и создайте ветку от `master`.
2. Соберите и проверьте изменения локально:

   ```bash
   make install
   make check
   ```

   `make check` включает ESLint, `tsc`, Vitest, Rust-тесты, `rustfmt`, `clippy` и
   `cargo-deny`. Отдельные цели — в `docs/build.md`.
3. Добавьте тесты на новое поведение. Конвертеры форматов проверяются golden-файлами
   в `tests/fixtures`, фронтенд — Vitest.
4. Обновите документацию, если меняются форматы, IPC, ограничения или сборка.
5. Откройте pull request в `master` и опишите мотивацию, поведение до/после и способ
   проверки.

## DCO

Проект принимает вклады по [Developer Certificate of Origin 1.1](DCO). Отдельного
CLA нет: авторские права остаются у автора, код распространяется под MIT.

Каждый коммит должен содержать строку `Signed-off-by` с именем и адресом автора:

```bash
git commit -s -m "fix: описание"
```

Git подставит `Signed-off-by: Имя <email>` из настроек `user.name` и `user.email`.
Если забыли — исправьте последний коммит `git commit --amend -s`, для нескольких —
`git rebase --signoff master`. CI-проверка падает, если хотя бы в одном коммите PR
нет корректной подписи.

## Стиль

- Сообщения коммитов — Conventional Commits на русском: `fix:`, `feat:`, `docs:`,
  `test:`, `refactor:`, `chore:`.
- Rust: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
  ошибки — через `AppError`, без паник на пользовательском вводе.
- TypeScript: ESLint без исключений, строгие типы, строки интерфейса — в
  `src/i18n/ru.ts`.
- Не добавляйте комментарии, которые пересказывают код.
- Не коммитьте секреты, сертификаты подписи и ключи автообновления: они живут только
  в секретах CI.

## Лицензия вклада

Отправляя pull request, вы соглашаетесь, что вклад распространяется под
[MIT](LICENSE), и подтверждаете это подписью DCO.
