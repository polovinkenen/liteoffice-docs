# ADR 0001: библиотека для DOCX

Статус: принято · Дата: 2026-11-17

## Контекст

WLite импортирует и экспортирует DOCX (OOXML, zip-пакет с XML-частями).
Нужны чтение и запись абзацев, runs, заголовков, списков, таблиц со
span, изображений, гиперссылок, разрывов страниц и базовых колонтитулов.

## Варианты

### `docx` 1.1.2

- Только генерация DOCX; чтения нет.
- Старый `strong-xml` и `zip 0.5`, ограниченный набор элементов.
- Не подходит: импорт пришлось бы писать полностью самостоятельно.

### `docx-rs` 0.4.22

- Чтение (`read_docx`, `read_docx_with_options`) и запись (`Docx::build/pack`).
- Есть структуры Document/Paragraph/Run/Table/Numberings/Styles/Header/Footer,
  картинки, ссылки, поля, стили заголовков.
- Читает media и relationships, умеет `Styles::create_heading_style_map`.
- Активно развивается; MIT.
- Ограничения: часть полей приватна — доступ через `serde_json`; экспорт
  изображений через `Pic::new` переводит их в PNG; часть экзотических
  конструкций (SmartArt, диаграммы, рецензирование) не разбирается.

### Собственный парсер поверх `zip` + `quick-xml`

- Максимальный контроль и точное покрытие схемы.
- Слишком большой объём для MVP: OOXML содержит десятки частей и relationship-
  граф; дублирование работы `docx-rs` не оправдано на этом этапе.

## Решение

Используем **`docx-rs 0.4.22`**, версия пиннится. Неподдержанные конструкции
попадают в `warnings`, а не ломают документ. Для zip-bomb защиты перед
`read_docx` выполняется собственная проверка архива через `zip 8.6`.

## Последствия

- Приватные поля `RunProperty`/`ParagraphProperty`/`TableCellProperty` читаются
  через их `Serialize`-представление (`serde_json`).
- Изображения при экспорте могут быть перекодированы в PNG.
- Обновление `docx-rs` требует прогона golden-тестов импорта/экспорта.
