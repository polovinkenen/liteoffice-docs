# Приёмка LiteOffice Docs

Документ фиксирует, что проверяется автоматически, что требует ручного прогона и
какие пункты остаются открытыми. Команды сборки и CI описаны в
[build.md](build.md), поддержка форматов — в [formats.md](formats.md), известные
ограничения — в [limitations.md](limitations.md).

Актуальные числа на момент составления: 187 Rust-тестов в `cargo test --workspace`
(плюс 1 `#[ignore]`-тест: perf-бенчмарк, он же проверяет лимит токенов RTF) и 97
frontend-тестов в 20 файлах
(`npm run test`).

## Матрица форматов

| Формат | Автоматические проверки | Round-trip | Предупреждения и деградации | Ручная проверка |
|---|---|---|---|---|
| TXT | `formats-txt`, 7 тестов: разбор абзацев и `hardBreak`, нормализация CRLF/CR, пустой файл, экспорт plain text, warning о потере разметки | да: plain text без потерь | только текст; списки маркерами, таблица через ` \| `, `pageBreak` и `hr` линией `---`; разметка теряется с warning | открытие/сохранение кириллицы, BOM и CRLF-файла, «Сохранить как» в TXT |
| Markdown (GFM) | `formats-markdown`, 26 тестов: заголовки, списки и task-списки, вложенность, таблицы, код, ссылки, изображения, `pageBreak`, экранирование, лимиты глубины и узлов, фильтр ссылок | да: поддерживаемые узлы, списки и таблицы стабильны | выравнивание, отступы, интервалы, `textStyle`, `highlight` и `underline` не сохраняются; объединённые ячейки упрощаются с warning; HTML и сноски пропускаются с warning | открытие GFM-файла с таблицей и task-списком, сохранение и повторное открытие |
| HTML | `formats-html`, 21 unit-тест и 1 golden-тест по 3 фикстурам (`basic`, `sanitize`, `tables`): блоки, стили, таблицы со span, task-списки, `data-page-break`, санитизация, запрет внешних изображений, лимиты | да: импорт → экспорт → импорт по golden | удаляются `script`/`style`/`form`/`iframe`/`object`/`svg`; `javascript:`-ссылки отбрасываются; внешние и относительные изображения не загружаются; неизвестные теги дают warning | открытие HTML в браузере, проверка санитизации вручную, сохранение и повторное открытие |
| RTF | `formats-rtf`, 27 unit-тестов и 1 golden-тест по 3 фикстурам (`basic`, `tables`, `unsupported`): лексер, декодирование ANSI и `\uNNNN`, runs и абзацные атрибуты, списки, таблицы, изображения, ссылки, лимиты токенов и узлов | да: поддерживаемые узлы и атрибуты | колонтитулы, сноски, комментарии, объекты, фигуры, emf/wmf и объединённые ячейки пропускаются с warning; цитаты становятся абзацами, код — моноширинным текстом, task-списки — маркерами | открытие в TextEdit/Cocoa RTF, Word и LibreOffice, проверка предупреждений при импорте сложного файла |
| DOCX | `formats-docx`, 19 unit-тестов и 1 golden-тест по 2 фикстурам (`basic`, `wordlike`): runs, заголовки, списки, таблицы со span, изображения, ссылки, page break, preflight zip-архива и лимиты | да: заголовки, списки, таблицы со span, изображения | колонтитулы, сноски, оглавление, поля PAGE, рецензирование, SmartArt и текстовые поля пропускаются с warning; одновременный rowspan+colspan упрощается | открытие в Word и LibreOffice, проверка `unzip -t`, сохранение и повторное открытие |
| PDF | `export-pdf`, 13 unit-тестов и 5 интеграционных в `tests/render.rs`: богатый документ, 50+ страниц с таблицами и изображениями, Letter/landscape `MediaBox`, извлечение текста, опции, колонтитулы и нумерация | не применимо (только экспорт) | неизвестные узлы и марки пропускаются с warning; внешние изображения не встраиваются; шрифты вне Liberation заменяются, отсутствующие глифы дают warning | открытие PDF в Preview/Chrome/Acrobat, проверка полей, ориентации, колонтитулов, нумерации и разрывов страниц |

## Автоматические проверки и команды

| Команда | Что проверяет |
|---|---|
| `make check` | `npm run lint`, `npm run typecheck`, `npm run test`, `cargo test --workspace`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo deny check -W unmaintained`. |
| `cargo test --workspace` | 187 Rust-тестов: `liteoffice-docs` 10, `app-core` 33, `docmodel` 8, `export-pdf` 18, `formats` 1, `formats-core` 14, `formats-docx` 20, `formats-html` 22, `formats-markdown` 26, `formats-rtf` 28, `formats-txt` 7. |
| `cargo deny check -W unmaintained` | Адвизории, лицензии, источники и дубликаты зависимостей; unmaintained-адвизории печатаются как warning и не роняют проверку. |
| `cargo test -p formats --test perf -- --ignored --nocapture` | Импорт ~300 страниц (300 × 25 абзацев) для TXT, Markdown, HTML, RTF и DOCX, разбор JSON модели и `PmDoc::validate`, а также проверка, что 300-страничный RTF не упирается в лимит токенов; печатает медиану, минимум и пиковый прирост памяти. Пороги: 2000 мс и 500 МБ. |
| `cargo +nightly fuzz run <target> -- -max_total_time=60 -rss_limit_mb=2048` | 5 таргетов импорта: `markdown_import`, `html_import`, `rtf_import`, `txt_import`, `docx_import`; входные данные длиннее 1 МиБ пропускаются. |
| `npm run test` | 97 frontend-тестов в 20 файлах: редактор и панель, вкладки, поиск и замена, автосохранение и восстановление, настройки, стартовый экран и недавние, PDF-диалог, файловые операции. |
| `npm run lint`, `npm run typecheck` | ESLint и `tsc --noEmit`. |
| `cargo fmt --all -- --check` | Форматирование Rust-кода. |
| `cargo clippy --workspace --all-targets -- -D warnings` | Линт Rust, предупреждения — ошибки. |
| `npx tauri build --no-bundle` | Release-бинарник без установщика; подтверждает, что приложение собирается целиком. |

Golden-тесты HTML, RTF и DOCX запускаются обычным `cargo test` и сравнивают
импорт/экспорт с эталонами в `tests/fixtures/`. Эталоны обновляются осознанно:

```bash
for crate in formats-html formats-rtf formats-docx; do
  UPDATE_GOLDEN=1 cargo test -p "$crate" --test golden
done
```

## CI

- `checks` (Ubuntu 22.04): системные зависимости, `npm ci`, `npm run lint`,
  `npm run typecheck`, `npm run test`, `cargo fmt --all -- --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`
  и `cargo deny check -W unmaintained`.
- `checks-cross-platform` (macOS и Windows): `npm ci`, `npm run lint`,
  `npm run typecheck`, `npm run test`, `cargo test --workspace` и `cargo clippy`
  без Linux-пакетов.
- `bundle`: установщики `.dmg` (macOS arm64), `.exe` (NSIS) и `.msi` (Windows),
  `.deb` и `.AppImage` (Linux); артефакты Actions хранятся 30 дней.
- `release`: по тегу `v*` сверяет версии, запускает проверки и бандлы, прикрепляет
  установщики к GitHub Release.
- `fuzz`: еженедельно по расписанию и вручную прогоняет все 5 таргетов по 60 секунд.

## Ручной чек-лист приёмки

Установка:

- [ ] macOS: `.dmg` монтируется, `LiteOffice Docs.app` копируется в «Программы» и
      запускается (для неподписанной сборки — правый клик → «Открыть»).
- [ ] Windows: `.msi` и `.exe` (NSIS) устанавливаются, приложение запускается,
      SmartScreen обходится через «Подробнее» → «Выполнить всё равно».
- [ ] Linux: `.deb` ставится через `dpkg -i`, `.AppImage` запускается после
      `chmod +x`.

Документы и форматы:

- [ ] открытие каждого формата: TXT, Markdown, HTML, RTF, DOCX;
- [ ] сохранение и «Сохранить как…» в каждый формат, повторное открытие файла;
- [ ] файл с кириллицей и CRLF открывается без искажений;
- [ ] объединённые ячейки, task-списки и разрыв страницы переживают round-trip в
      поддерживаемых форматах;
- [ ] предупреждения о деградациях показываются в баннере и соответствуют потерям.

PDF, печать и восстановление:

- [ ] «Экспорт в PDF…»: A4 и Letter, книжная и альбомная ориентация, поля,
      колонтитулы с `{page}`/`{pages}`, нумерация страниц;
- [ ] «Предпросмотр» открывает временный PDF системным просмотрщиком;
- [ ] PDF открывается в Preview/Chrome/Acrobat, разрывы страниц и таблицы корректны;
- [ ] «Печать…» (`Cmd/Ctrl+P`) показывает системный диалог и печатает без интерфейса;
- [ ] автосохранение документа с путём пишет в сам файл, маркер изменений снимается;
- [ ] черновик нового документа предлагается к восстановлению после перезапуска,
      отказ удаляет черновик.

Интерфейс:

- [ ] вкладки: открытие нескольких файлов, дедупликация, закрытие с подтверждением;
- [ ] недавние документы и меню «Файл → Недавние», очистка списка;
- [ ] настройки: системная/светлая/тёмная тема, переключатель автосохранения;
- [ ] drag&drop файлов на окно с оверлеем;
- [ ] таблицы: вставка до 6×6, добавление и удаление строк/столбцов, объединение и
      разделение ячеек;
- [ ] изображения: вставка из файла, отображение, сохранение в HTML/Markdown/RTF/DOCX;
- [ ] task-списки: отметка, вложенность, сохранение в Markdown/DOCX.

Производительность:

- [ ] документ на 300 страниц открывается и прокручивается без заметных задержек;
- [ ] вывод `cargo test -p formats --test perf -- --ignored --nocapture`
      укладывается в 2000 мс и 500 МБ на каждый сценарий;
- [ ] набор текста в документе на 300 страниц остаётся плавным.

## Открытые пункты

- Подпись и нотаризация: macOS Developer ID и Windows code signing ждут получения
  сертификатов; до этого установщики неподписанные.
- Ассоциации файлов и открытие двойным кликом — отдельная задача, в текущий объём
  не входят.
- Smoke-тесты установки на чистых Windows и Linux не автоматизированы; установка
  проверяется вручную.
- «Плавный ввод» на большом документе не измеряется бенчмарком: `perf` покрывает
  только импорт ядра и `validate`, без вебвью, ввода и IPC. Требуется ручная
  проверка.
