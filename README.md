# WLite

Кроссплатформенный (macOS, Linux, Windows) редактор документов — аналог Word для
повседневных задач. Ядро на Rust, интерфейс на React и TipTap, оболочка на Tauri 2.

## Статус

Работают окно приложения, WYSIWYG-редактор, несколько документов во вкладках, открытие
и сохранение TXT, Markdown, HTML, RTF и DOCX, вставка изображений и таблиц, печать,
нативные диалоги, защита от потери изменений, валидация модели документа и экспорт
PDF с постраничной вёрсткой.

Реализовано сейчас:
- редактор TipTap: заголовки, bold/italic/underline/strike, маркированные,
  нумерованные и task-списки, цитаты, блоки кода, таблицы, изображения, undo/redo;
- placeholder в пустом документе и счётчик слов/символов в редакторе (на стартовом
  экране скрыт);
- расширенное форматирование: шрифт, размер, цвет текста, выделение, выравнивание,
  отступы, межстрочный интервал и интервалы до/после абзаца, ссылки, очистка
  форматирования;
- панель форматирования в две строки без горизонтальной прокрутки; селект шрифта
  показывает шрифт в позиции курсора и «Смешанный» для выделения с разными шрифтами;
- вкладки документов: отдельный редактор и история undo/redo на вкладку, кнопка «+»
  открывает вкладку с начальным экраном («Новый документ» / «Открыть…»), закрытие,
  маркер несохранённых изменений;
- открытие нескольких файлов за раз; уже открытый файл не дублируется;
- drag&drop файлов на окно с оверлеем «Отпустите файлы, чтобы открыть»;
- липкая шапка с вкладками «Главная» и «Вставка»;
- вкладка «Вставка»: изображение, таблица с выбором размера до 6×6, разделитель
  страниц; изображения хранятся в `<app-data>/assets` и встраиваются при экспорте;
- панель управления таблицей при курсоре в ней: +/− столбцы и строки, объединение и
  разделение ячеек, удаление;
- разрыв страницы, который сохраняется в Markdown маркером `<!-- pagebreak -->`, а в
  HTML — блоком `data-page-break`;
- поиск и замена по тексту с подсветкой совпадений, учётом регистра и режимом
  «слово целиком» (`Cmd/Ctrl+F`);
- автосохранение: документы с путём записываются в сам файл через 1,5 секунды после
  правки, новые документы сохраняются как черновики в каталог данных приложения;
- настройки в шестерёнке справа сверху: тема (системная, светлая, тёмная) и
  переключатель автосохранения;
- стартовый экран с кнопками «Новый документ» и «Открыть…», список недавних
  документов и подменю «Недавние» в меню «Файл»;
- открытие и сохранение `.txt`, `.md` / `.markdown`, `.html` / `.htm`, `.rtf` и `.docx`
  через Rust-конвертеры;
- выбор формата при первом сохранении и «Сохранить как…» (Markdown, HTML, RTF,
  DOCX, TXT): выбранный формат задаёт кодек и расширение файла;
- файловые действия в нативном меню приложения с акселераторами;
- печать текущего документа через системный диалог (`Cmd/Ctrl+P`);
- имя активного файла и признак несохранённых изменений в заголовке окна;
- подтверждение при закрытии изменённой вкладки, окна и выходе (Cmd+Q, Dock);
- предупреждения о неподдержанной разметке и потерях при сохранении в TXT;
- индикатор версии Rust-ядра;
- светлая и тёмная темы (следует системной);
- модель документа на базе ProseMirror JSON с валидацией и лимитами;
- CI: проверки на Ubuntu, macOS и Windows; сборка установщиков на трёх ОС — `.dmg`
  (macOS), `.exe` (NSIS) и `.msi` (Windows), `.deb` и `.AppImage` (Linux); см.
  «Установщики».

Планируется:
- колонтитулы и нумерация страниц в самом документе (в PDF они задаются при
  экспорте).

## Меню

Файловые действия и работа с буфером обмена находятся в системном меню (на macOS —
строка меню сверху экрана, на Linux и Windows — меню в верхней части окна):

- **WLite** — «О WLite», «Скрыть», «Выйти из WLite» (`Cmd+Q` с защитой
  несохранённых изменений);
- **Файл** — «Новый» (`Cmd+N`), «Открыть…» (`Cmd+O`), «Недавние» (последние
  открытые и сохранённые документы), «Сохранить» (`Cmd+S`), «Сохранить как…»
  (`Cmd+Shift+S`), «Экспорт в PDF…» (`Cmd+Shift+E`), «Печать…» (`Cmd+P`),
  «Закрыть документ» (`Cmd+W`), «Закрыть окно» (`Cmd+Shift+W`);
- **Правка** — «Отменить» (`Cmd+Z`), «Повторить» (`Cmd+Shift+Z`), «Вырезать»
  (`Cmd+X`), «Копировать» (`Cmd+C`), «Вставить» (`Cmd+V`), «Выделить все» (`Cmd+A`);
- **Окно** — «Свернуть», «Масштаб».

Выход через меню, Dock, закрытие изменённой вкладки или окна требует подтверждения.
На Windows и Linux вместо `Cmd` используется `Ctrl`.

## Экспорт PDF

«Файл → Экспорт в PDF…» (`Cmd/Ctrl+Shift+E`) открывает диалог параметров:
бумага A4 или Letter, книжная и альбомная ориентация, поля (пресеты и четыре
числовых значения в мм), верхний и нижний колонтитулы, нумерация страниц. В
колонтитулах доступны токены `{page}` — номер страницы и `{pages}` — всего
страниц.

- «Предпросмотр» собирает временный PDF в кэше приложения и открывает его
  системным просмотрщиком; «Экспорт…» предлагает выбрать путь и сохраняет файл.
- Вёрстка выполняется библиотекой Typst, поэтому постраничная разбивка в PDF
  точная, в отличие от непрерывного потока в редакторе.
- Шрифты Liberation Serif/Sans/Mono встроены в приложение; шрифты редактора
  подбираются к ближайшему Liberation, о замене сообщается в предупреждениях.
- Параметры экспорта запоминаются между запусками.

## Поиск и восстановление

- `Cmd/Ctrl+F` открывает панель поиска и замены; `Enter` и `Shift+Enter` переходят
  к следующему и предыдущему совпадению, `Esc` закрывает панель;
- поддерживаются учёт регистра и поиск слова целиком; все совпадения подсвечиваются,
  текущее выделяется контрастнее;
- изменения в документе с путём через 1,5 секунды после правки записываются в сам
  файл (атомарно, без диалога); после успешной записи вкладка перестаёт быть
  изменённой, черновик удаляется;
- новые документы без пути автосохраняются как черновики в `<app-data>/autosave`;
- при следующем запуске приложение предлагает восстановить найденные черновики.
  Если отказаться, черновики очищаются;
- при закрытии вкладки или выходе приложение спрашивает подтверждение, пока у
  вкладки стоит признак несохранённых изменений. У документа с путём этот признак
  снимается после автосохранения в сам файл; у нового документа без пути запись
  черновика его не снимает, поэтому подтверждение при закрытии появится и после
  автосохранения. При отказе от сохранения приложение отменяет автосохранение и
  удаляет черновик.

## Настройки

Шестерёнка в правом верхнем углу открывает настройки:

- тема — «Системная», «Светлая» или «Тёмная»; применяется сразу, системная следует
  настройке ОС;
- автосохранение — включение и выключение записи изменений в файл и создания
  черновиков. Выключение не удаляет уже существующие снимки: предложение восстановить
  их при следующем запуске остаётся;
- настройки сохраняются в `<app-data>/settings.json`.

## Стартовый экран и недавние

- кнопка «+» и новая пустая вкладка показывают стартовый экран с кнопками «Новый
  документ» и «Открыть…»; если открыть файл с этого экрана, пустая вкладка
  заменяется документом; после закрытия последнего документа стартовый экран
  открывается снова;
- на стартовом экране — список недавних документов; запись можно открыть или убрать;
- те же документы доступны в меню «Файл → Недавние»; список можно очистить;
- хранится до 15 записей в `<app-data>/recent.json`, новые сверху, дубликаты путей
  объединяются.

## Форматы

| Формат | Импорт | Экспорт | Примечание |
|---|---|---|---|
| TXT | да | да | UTF-8, абзацы разделяются пустой строкой, одиночный перенос — `hardBreak` |
| Markdown (GFM) | да | да | заголовки, обычные и task-списки (`- [ ]`/`- [x]`), код, цитаты, ссылки, изображения, таблицы; разрыв страницы — `<!-- pagebreak -->` |
| HTML | да | да | whitelist тегов и атрибутов, внешние ресурсы не загружаются |
| RTF | да | да | абзацы, runs, шрифты/размеры/цвет, выравнивание, списки, простые таблицы, изображения png/jpeg/gif, ссылки |
| DOCX | да | да | runs, заголовки, списки, таблицы со span, изображения, ссылки, page break; колонтитулы, сноски, оглавление, поля и рецензирование пропускаются с warning |
| PDF | — | да | Typst: A4/Letter, поля, ориентация, колонтитулы, нумерация страниц |

Ограничения текущей итерации:
- текстовые форматы TXT/Markdown/HTML читаются в UTF-8; RTF декодирует ANSI-кодировки
  по `\ansicpg`, DOCX читается как бинарный архив;
- изображения хранятся как assets в `<app-data>/assets` (лимит 15 МБ, форматы png/
  jpg/jpeg/gif/webp, без SVG); при экспорте в Markdown встраиваются как `data:` URL,
  поэтому файл может получиться большим;
- кэш assets пока не очищается автоматически: файлы остаются после удаления
  документов;
- таблица вставляется размером до 6×6 с заголовком; объединённые ячейки
  поддерживаются в редакторе, но в Markdown сохраняются как обычные с warning;
- разрыв страницы сохраняется в Markdown маркером `<!-- pagebreak -->`; в TXT он
  выводится как линия и не восстанавливается при открытии;
- шрифт, размер, цвет, выравнивание, отступы и интервалы сохраняются в модели
  документа и в HTML; при экспорте в Markdown/TXT они теряются с предупреждением;
- при импорте HTML scripts, styles, формы, фреймы и обработчики событий удаляются,
  ссылки с `javascript:` отбрасываются, внешние и относительные изображения не
  загружаются; неподдержанные теги попадают в предупреждения;
- разрыв страницы в HTML — `<div data-page-break="true"></div>`, task-списки —
  маркеры `data-type="taskList"` / `data-type="taskItem"`;
- RTF: ANSI-кодировки (cp1251 и родственные) декодируются автоматически; списки
  сохраняются настоящими list table, заголовки — стилями, картинки встраиваются как
  `\pict`; колонтитулы, сноски, объекты, фигуры, emf/wmf и объединённые ячейки
  пропускаются с warning; task-списки в Word выглядят как маркеры `[x]`/`[ ]`, блоки
  кода — как моноширинный текст;
- DOCX: списки и заголовки экспортируются стилями и numbering, таблицы — с
  `gridSpan`/`vMerge`, картинки встраиваются как media (при экспорте переводятся в
  PNG); колонтитулы, сноски, оглавление, поля PAGE и рецензирование не поддерживаются
  и попадают в warnings; zip-архив проверяется на размеры и сжатие до разбора;
- сноски и сырой HTML в Markdown пропускаются с предупреждением;

### Fuzz-тесты импорта

Каркас cargo-fuzz лежит в `fuzz/` (вне workspace, чтобы не замедлять обычные
проверки). Таргеты: `markdown_import`, `html_import`, `rtf_import`, `txt_import`,
`docx_import`. Нужны nightly и cargo-fuzz:

```bash
rustup toolchain install nightly --profile minimal
cargo install cargo-fuzz --locked
cargo +nightly fuzz run markdown_import -- -max_total_time=60 -rss_limit_mb=2048
```

Входные данные длиннее 1 MiB пропускаются. Упавшие примеры складываются в
`fuzz/artifacts/<target>/`, корпус — в `fuzz/corpus/<target>/`; оба каталога в
`.gitignore`. Еженедельный прогон всех таргетов выполняет workflow `Fuzz`.

## Бенчмарки производительности

Сквозной бенчмарк импорта ядра:

```bash
cargo test -p wlite-formats --test perf -- --ignored --nocapture
```

Документ объёмом ~300 страниц (300 × 25 абзацев) генерируется детерминированно на
русском языке (кириллица). Для каждого сценария выполняется прогревочный импорт,
затем три замера; в таблицу попадают медиана, минимум и пиковый прирост памяти.

Что меряется:
- импорт core-кодеков: TXT, Markdown, HTML, RTF, DOCX;
- разбор JSON модели документа и `PmDoc::validate` — как ориентир для IPC.

Что не меряется:
- вебвью и React/TipTap: рендер, ввод, прокрутка и стоимость IPC;
- экспорт документов и PDF-вёрстка.

Пороги по умолчанию — 2000 мс медианы и 500 МБ пикового прироста памяти на каждый
сценарий. Они переопределяются переменными окружения `WLITE_PERF_MAX_MS` и
`WLITE_PERF_MAX_MB`.

Куда смотреть при провале:
- RTF — лимит `MAX_TOKENS` в `crates/formats-rtf/src/lexer.rs` (кириллица
  записывается как `\uNNNN?`, то есть примерно два токена на символ) и стоимость
  лексера/парсера;
- DOCX — распаковку zip и построение модели;
- память — лимиты импорта (`MAX_NODES`) и размер промежуточных токенов.
Фактическую таблицу чисел всегда печатает сам тест.

## Установщики

CI собирает установщики на трёх ОС:
- macOS arm64 — `.dmg`;
- Windows x64 — `.exe` (NSIS) и `.msi`;
- Linux x64 — `.deb` и `.AppImage`.

Workflows:
- `CI` — проверки, а на push в `master`/`main` и по ручному запуску ещё и бандлы;
- `Bundles` — общая сборка установщиков для CI и релизов;
- `Release` — по тегу `v*` собирает установщики и прикрепляет их к GitHub Release.

Скачать сборку:
- из GitHub Releases — готовые файлы после релиза;
- из Actions → нужный run → Artifacts (`wlite-macos-arm64`,
  `wlite-windows-x64`, `wlite-linux-x64`).

Локальная сборка macOS:
```bash
npx tauri build --target aarch64-apple-darwin --bundles dmg
# target/aarch64-apple-darwin/release/bundle/dmg/WLite_0.1.0_aarch64.dmg
```

Релиз:
```bash
git tag -a v0.1.0 -m "WLite 0.1.0"
git push origin v0.1.0
```

Подписи пока не настроены, поэтому установщики неподписанные:
- macOS: правый клик по `WLite.app` → «Открыть» либо
  `xattr -dr com.apple.quarantine /Applications/WLite.app`;
- Windows: SmartScreen → «Подробнее» → «Выполнить всё равно»;
- Linux: `sudo dpkg -i wlite_*.deb` или `chmod +x WLite_*.AppImage`.

## Модель документа

Источник истины — ProseMirror JSON (схема v1, корневой узел `doc`). Rust-ядро
проверяет структуру: тип корня, текстовые узлы без детей, лимиты глубины (256) и числа
узлов (1 000 000). Атрибуты узлов и марок хранятся как JSON, поэтому схема расширяется
без изменения Rust-типов.

Файловые операции:
- чтение — UTF-8 с BOM, лимит 50 МБ;
- запись — атомарная (временный файл и rename), исходный файл не повреждается при
  ошибке;
- формат определяется по расширению, неподдерживаемое расширение возвращает
  `unsupported_format`;
- ошибки IPC имеют единый вид `{ code, message }`.

## Ограничения

- Открытые вкладки живут в памяти. После перезапуска восстанавливаются только
  черновики новых документов; файлы с путём автосохраняются на диск, а чистые вкладки
  не сохраняются. «Сохранить все» — позже.
- Пагинация в редакторе приблизительная: документ отображается непрерывным потоком в
  A4-рамке. Печать использует встроенный диалог печати webview и CSS `@media print`
  без колонтитулов и точной вёрстки; точная постраничная вёрстка — при экспорте PDF.
- В PDF изображения масштабируются по ширине полосы набора; шрифты вне Liberation
  заменяются, а отсутствующие глифы (например, цветные эмодзи) дают предупреждение.
- Поддержка DOCX/RTF частичная: сложные конструкции Word (SmartArt, диаграммы,
  рецензирование, колонтитулы) пропускаются с предупреждением.
- ODT, импорт PDF, сноски, оглавление, рецензирование и совместное редактирование
  в текущий объём не входят.
