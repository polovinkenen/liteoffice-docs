# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят для последнего опубликованного релиза LiteOffice
Docs. Более старые версии не поддерживаются — обновитесь до актуального релиза с
GitHub Releases.

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте приватный канал GitHub: вкладка
**Security** → **Report a vulnerability** (GitHub Security Advisories). Если канал
недоступен, напишите мейнтейнеру напрямую на адрес из профиля GitHub.

В отчёте укажите:

- версию приложения, ОС и архитектуру;
- шаги воспроизведения или минимальный файл-триггер;
- ожидаемое и фактическое поведение, влияние (падение, чтение файлов, выполнение
  кода, утечка данных);
- известные обходные пути.

Файлы прикладывайте только если они не содержат персональных данных; при
необходимости замените конфиденциальное содержимое.

## Что считается уязвимостью

- обход лимитов импорта (размер, глубина, число узлов, zip-bomb, таймауты);
- паники, зависания и неконтролируемое потребление памяти на недоверенных DOCX,
  RTF, Markdown, HTML и TXT;
- выход за пределы разрешённых путей и произвольный доступ к файловой системе через
  IPC;
- обход CSP, санитизации HTML или ограничений внешних ссылок;
- подмена обновлений и компрометация канала доставки;
- утечка содержимого документов в сеть.

## Процесс

- Подтверждаем получение отчёта в течение 7 дней.
- Согласуем срок раскрытия: обычно фикс и релиз, затем публикация advisory с
  указанием автора отчёта (если он не против).
- Не тестируйте на чужих данных и системах. Публичная эксплуатация до выхода фикса
  не допускается.
- Вознаграждений за отчёты нет.
